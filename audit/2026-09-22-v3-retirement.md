# Retirement of the Uniswap V3 findings

On 2026-09-22 Xindex moved pricing from Uniswap V3 pool time-weighted means to Chainlink USD feeds, and execution from
SwapRouter02 to Uniswap's Universal Router 2.0.0, which reaches both V3 and V4 pools with the venue chosen per leg.
The reasons are in `ARCHITECTURE.md` under "Why Chainlink, and why the Universal Router"; the short version is that
Uniswap V4 carries no oracle at all, so following the liquidity to V4 meant leaving Uniswap for prices, and the
Universal Router still reaches V3 depth, so execution could follow the liquidity without giving up the pools that are
still deeper.

That is a change of mechanism, not a change of behaviour, so some past findings no longer describe anything in the
repository. This file says which, and what happened to the property each one protected. It does not restate the
findings: `audit/triage.md` (2026-09-16, `XA..`), `audit/2026-09-18-logic-review.md` (`LR..`) and
`audit/2026-09-19-triage.md` (`DA..`) still hold the originals, and the v1 and `R..` findings are in the v1 report.

Corrected on 2026-09-23, after the security audit of that date checked this file against the git history (CR-I21 in
`audit/2026-09-23-security-audit.md`). The R01 to R03, XA-01, I02, I03 / FR01, I12 / XA-08 and XA-30 rows described
their findings or their tests wrongly, and R07, XA-13, XA-24, XA-39 and LR-07 had lost or narrowed a test or a guard
under their own ids with no row here at all, which by this file's own rule declared them unaffected. The corrected
rows say what each one was; the rows marked 2026-09-23 also say what that audit changed.

Dispositions here extend the usual set with one more:

- **RETIRED:** the mechanism the finding lived in is gone. The evidence names the test that was removed and the
  property, if any, that survives elsewhere.
- **RE-TARGETED:** the finding still binds, against the new mechanism. The evidence names where its test is now and
  what changed inside it.
- **UNAFFECTED:** everything not listed. The mechanism, the fix and the test are untouched.

A retired id is not free to reuse and its test must not be restored against the new design. If the property matters
here, it gets a new id from the review of this surface.

## Unaffected

Everything not listed above. In particular every in-kind property of `IndexToken` is untouched: its executable code was
unchanged by the move itself, it names no price source and no venue, and `MIN_TURNOVER` and `MIN_SETTLEMENT_RATIO` are
ratios, which reprice with the market. Its one behavioural change in v3 is VR-04, which the merge of the verification
review (`8fab3ba`) brought in: cancelling an auction that already expired no longer re-arms `REBALANCE_DELAY`. This
paragraph first called the contract byte-identical across the change, which its deployed bytecode never was, since the
metadata hash moves with every NatSpec edit, and which the merge made untrue of its executable code as well (CR-I20).

It also argued that `MIN_SETTLEMENT_RATIO`'s 5% allowance, derived for a thirty-minute mean against spot, was more
conservative against a feed with a 0.5–2% deviation threshold, and so did not change. That was not measured, and it is
wrong: a deviation threshold bounds how far an answer drifts before the next round, not how far it sits from the market
during a fast move, when a round lands a minute or two late. Replaying 26 months of answers against exchange prices,
the 2026-09-23 audit found a lone executor at the 0.9 floor keeping more than the documented 15% of the traded value in
about 4% of auctions, up to about 21%, so the ratio was raised to 0.875 (CR-L06).

## What this does not cover

The new surface — the single price path, `CompositeFeed`, the Universal Router integration and the V4 legs — had no
security review of its own when this file was written. That review is `CR`, and it comes before the external human
audit and before mainnet. It ran on 2026-09-22 and 2026-09-23 against `855e41b`: `audit/2026-09-23-security-audit.md`,
triaged in `audit/2026-09-23-triage.md`.
