## Second pass, 2026-09-20

The owner asked that every finding closed with words be closed with code wherever a sound fix exists. Five moved to
FIXED (DA-03, DA-05, DA-10, DA-11, DA-18); their rows above carry the evidence. Six stay DOCUMENTED, and each is a case
where no code fix exists rather than one nobody wrote:

- **DA-04.** The griefer's shallow block and XA-01's push through an empty range are the same on-chain event: twelve
  seconds at liquidity one, in one sub-window. No check can reject the attack and accept the grief, only move the
  tolerance between them, which is what the first pass found when the median-liquidity fix turned
  `test_XA01_aSnapshotThroughAnEmptyRangeCannotStart` from `ThinPriceHistory` into `PriceHistoryDeviates`.
- **DA-07.** Refusing a config against a pool with no in-range liquidity is the correct conservative behaviour;
  `ThinPriceHistory(pool, 0, min)` says exactly that. The only "fix" is accepting `minLiquidity` of zero, which turns
  off the XA-01 floor for that token.
- **DA-12.** See its row: the stall is bounded by the owner replacing the guardian, and the proposed rate limit costs
  more than it saves.
- **DA-19.** Already enforced, and the finding is stale: `_checkPool` calls `_observe`, which asks the pool for a full
  `TWAP_WINDOW` average, so a ring that cannot serve one reverts `OLD` whatever its cardinality says. Cardinality is
  not the only gate.
- **DA-21** was a documentation defect to begin with.
- **DA-23.** An on-chain symbol registry would make squatting permanent in a system with no admin to unstick it, and
  homoglyphs walk past it; the CREATE2 salt already commits to the name and the symbol, so addresses differ. It stays
  an app-level display rule.

4. **DA-11's new grief.** Listing execution can now be held off by keeping a pool thin, which the first pass judged the

Three things follow, and the first was not expected.

**Trading frequency does not track depth.** ENA (187 WETH) and ONDO (94) never go stale at any threshold, while LINK
(2,193) is stale 43% of the time at ten minutes and OHM (956) 75%. Any reasoning of the form "the deep pools trade
constantly, so the age check will not bind there" is wrong, and the earlier draft of this work assumed it.

**One sub-window was too strict.** A WBTC / WETH / LINK / UNI / AAVE index could have started a rebalance only 38% of
the time at ten minutes, against 69% at twenty. `startRebalance` is permissionless and retryable, so neither figure
makes rebalancing impossible, but the stricter bound taxed the deep pools for no security gain, because the deviation
check is load-bearing at any age below the full window.

**Depth has moved since the 2026-09-17 table**, most of all ENA, 87 to 187 WETH. The `minLiquidity` floors in
`MainnetAddresses.sol` derive from those older readings and should be re-measured before mainnet.

## Corrections of 2026-09-23

The security audit of 2026-09-23 (`audit/2026-09-23-security-audit.md`, ids `CR-..`, triaged in
`audit/2026-09-23-triage.md`) found six of these rows incomplete or resting on a claim that did not hold. The rows above
say what was done on 2026-09-19 and 2026-09-20; this says what changed since.

- **DA-05.** The row's bound, 15% of the traded value, holds at the feed prices the settlement reads, not at the
  market's: a feed's answer can sit further from the market than its deviation threshold during a fast move, and a
  replay of 26 months of answers measured a lone executor keeping more than 15% in about 4% of auctions, up to about
  21% (CR-L06). `MIN_SETTLEMENT_RATIO` is 0.875 now, and the bound is stated as 12.5% at feed prices plus the
  feed-to-market gap. The constant, its rounding and the rule's valuation rounding had no test that failed when they
  changed (CR-I28): `test_DA05_CRI28_theSettlementFloorSitsExactlyOnTheRatio`,
  `test_CRI28_eachLegOfASettlementIsValuedRoundedDown` and `test_CRL06_aDriftTheOldRatioLetThroughIsRefusedAtTheFloor`
  in `test/IndexToken.rebalance.t.sol` pin them. The row's "a quiet pool" is a stale feed since the move to Chainlink.
- **DA-08.** `test_DA08_turnoverCountsOnlyWhatIsActuallyTraded` could not see a mutant that measured `sold` alone,
  because on a value-scale-1 basket the target is never worth less than the holding, so `min(sold, bought)` always
  equals `sold` there (CR-I24). `test_DA08_CRI24_turnoverIsTheSmallerSideWhenRoundingSplitsThem` in
  `test/IndexRule.t.sol` uses a basket on the WAD value scale, where the two differ.
- **DA-10.** Deleting the exclusion list left the other live read in place: a config without a reference supply made
  the rule read the token's own `totalSupply` inside the snapshot, and the shipped wstETH entry was listed that way.
  `unwrap` burns wstETH and `wrap` mints it, and a third of the supply could be flash-borrowed at no fee, so a stranger
  could move wstETH's market cap inside the transaction that called `startRebalance` — the class this row says the
  deletion closed (CR-M01). Every config now carries a reference supply (`checkConfig` reverts `ZeroSupply`), and the
  rule reads no supply live. The row's "its own `totalSupply` or a reference figure" is now "a reference figure".
- **DA-16.** The getters' own NatSpec still described the trap this row closed, documenting `listingEta` and
  `pendingGuardianEta` as zero when nothing is pending (CR-I16); it now points at the two views. The boundaries the
  views answer on are pinned by `test_CRI33_aListingIsPendingAtTheLastMomentItCanExecute` and
  `test_CRI33_anExecutedListingLeavesNoPendingFlag` in `test/IndexFactory.t.sol`.
- **DA-18.** The bound was skipped whenever either side was zero, as "a change of kind", and a zero reference supply
