# WBT check for the Stage A list (2026-09-30)

The spec (section 8) keeps WBT, WhiteBIT's token, off the Stage A list until three things are checked:
- its reference supply;
- its admin powers;
- its Ethereum execution depth.

Measured on mainnet at block 26,088,380, from `0x925206b8a707096Ed26ae47C84747fE0bb734F59`, the Ethereum contract
CoinPaprika lists for `wbt-whitebit`. Supply figures are from CoinPaprika on 2026-09-29.

## Reference supply

| Figure | Amount |
|---|---|
| Market cap / price ($9.998B / $84.13) | about **118.9M** WBT circulating |
| Total supply | 293.4M WBT (max 400M) |
| On Ethereum (`totalSupply()`, 8 decimals) | 165,421,669 WBT |

The issuer holds most of the supply, so the reference must be the circulating figure, about 118.9M. It must not be
the total, or the Ethereum `totalSupply()`, which alone exceeds the circulating supply. With a circulating reference,
WBT's weight in the flagship is about 0.43%.

## Admin powers of the Ethereum contract

The dispatcher has 22 functions, all decoded:

| Power | Present | Note |
|---|---|---|
| Mint | no | the Ethereum supply can only fall, through `burn` |
| Upgrade | no | no proxy slot; about 8.4 KB of runtime code |
| Pause every transfer | **yes** | `pause()` / `unpause()`, not paused now |
| Blacklist any account | **yes** | `blacklistAccount(address,bool)`, `isBlacklisted(address)` |
| Destroy a blacklisted balance | **yes** | `destroyBlackFunds(address)` |
| Who holds them | a **single key** | `owner()` is `0xd77d461d51d356569ee281795Afd5eb62e2e8f0c`, an account with no code, not a multisig |

A pause would be a freeze like WBTC's, which the design already handles with `redeemSkipping`, claims and the keep mask.
The blacklist with `destroyBlackFunds` is different. One key could blacklist an index hub and zero its WBT. That
component's backing would then be gone for good, not frozen. Every holder would lose WBT's weight, and its claims could
never be paid. Tether has the same power over USDT. No Stage A component has it:
- WBTC's custodian can pause, but cannot destroy balances;
- WETH, LINK and UNI have no admin at all.

## Execution depth on Ethereum

| Venue | WBT pools against WETH, ETH, USDT, USDC |
|---|---|
| Uniswap V2 | none |
| Uniswap V3 (fees 0.01%, 0.05%, 0.3%, 1%) | none |
| Uniswap V4, hookless (the same fees at their standard tick spacings) | none with liquidity |

WBT's $139.6M of daily volume (1.4% of its market cap, so it passes the 0.1% screen) trades on centralized exchanges,
mostly WhiteBIT itself. On Ethereum that means:
- The zap cannot route a WBT leg, so indexes holding WBT mint and burn only in kind or through `MintRequests`.
- A rebalance's executor must source WBT off chain. At the floor list's 0.43% weight that is a small leg, but no
  on-chain competition sets its price, so a lone executor is the likely case.

## Conclusion

WBT passes the volume screen, and a circulating reference supply is available. It fails on two counts no other Stage A
component does:
- a single key can destroy a hub's WBT;
- no on-chain venue exists for executors or the zap.

**Recommendation: keep WBT off the Stage A list.** Stage A then holds WBTC, WETH, LINK and UNI, about 0.4 points less
coverage than with WBT. Reconsider WBT if its owner becomes a multisig or timelock that renounces
`destroyBlackFunds`, and an Ethereum pool with real depth appears.

This is the owner's decision; nothing in the code changes either way, since listing is a governance action.
